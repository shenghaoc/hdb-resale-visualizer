What the text below calls the frozen remote apply is the incremental atomic batch, now `writeIncrementalArtifactsToLocalD1`: it accepts only a loopback emulator and refuses a manifest that carries an unfinished marker. `--plan`, `--check-upstream` and `--apply-rehearsal` select the incremental modes (`--reconcile-*` is rejected without one of them), and `--force` keeps its original meaning on a plain run. The D1 client sends one attempt per request unless the caller opts in to retries, which the production publication does.

## Causes and implementation

The historical writer deleted and reinserted approximately 985,000 transactions for a daily increase of 134. Generated block/detail/comparison/trend tables were also replaced wholesale. Suggest issued multiple leading-wildcard scans per keystroke. Cache-Control alone did not populate Workers shared cache. The D1 REST client discarded billable metadata.

The client now records every attempted statement's table, phase, operation and actual response `rows_read`, `rows_written`, `duration`, `changes` and success. Unknown/missing metadata, mismatched response counts and transport ambiguity produce UNKNOWN totals. Failed JSON HTTP responses retain any returned metadata. D1 mutation requests are never automatically retried. SQLite `changes()` and returned-row counts are explicitly not billable metrics. Replanning requires a new budget assessment; resetting a client does not erase account usage or resolve an ambiguous remote timeout.

Transaction reconciliation matches exact canonical JSON tuples of the eleven existing source columns as a **multiset**. Duplicate-looking occurrences retain separate integer rowids; new occurrences receive unused integer rowids. No transaction schema/index migration, full-row identity backfill or table rebuild is introduced. Exact tuples avoid delimiter/hash collisions. Since HDB supplies no authoritative unique sale ID, a changed tuple cannot establish which physical sale was corrected.

A disappeared existing occurrence rejects normal refresh before writes. It is not inferred as a deletion, or retained alongside an unconditional replacement. The pure planner supports explicitly reviewed `rowid → replacement fact` pairs and validates both IDs and replacement multiplicities. The CLI exposes no automatic correction/deletion or bulk recovery override. Manual reconciliation remains required. Normal refresh never deletes/truncates transaction or generated tables.

Stable rowid-derived build IDs replace CSV-position tie ordering. Detail publication preserves existing presentation IDs by source-fact tuple/occurrence. New presentation IDs use SHA-256 plus occurrence; cryptographic collision resistance is an assumption for these presentation IDs only. Legacy unparseable storey facts remain excluded from comparable SQL, preserving the established source schema. They still affect other evidence: a manifest digest tracks their exact source multiset, derived computation invalidates conservatively, and the coordinator blocks unknown/changed excluded facts for explicit manual reconciliation. A missing prior digest with excluded facts is a bootstrap blocker, not permission to discard them.

## Derived dependency closure and contracts

Affected addresses drive block summaries/details. Affected town × canonical type cohorts drive trend medians and comparison peer populations. Corrections include old and new addresses/cohorts, and the prior latest cohort. Comparisons recompute the full peer closure because one changed sale can move otherwise untouched peers' percentiles. Unaffected objects are reused; persistence compares candidate values and writes only changed rows/columns. Unchanged timestamps and stored detail IDs remain unchanged.

The digest of property, MRT, geocode, amenity, walking-time context and the UTC lease year invalidates block/comparison calculations. A changed global maximum month invalidates comparison recency; a changed 24-observed-month threshold invalidates all block windows and comparisons. Source ingestion/grouping still traverses the full corpus; this is selective sorting/derived computation and changed-only persistence, not a fully incremental source download or read path.

Normalized transactions, capped recent-transaction detail JSON, full monthly trends and comparison JSON retain their API contracts. Large detail blobs use SQLite `json_set` only for changed owned roots (`summary`, `monthlyTrend`, `recentTransactions`). Arrays/objects/nulls retain JSON types; unknown legitimate top-level fields survive publication. Missing required candidate roots fail validation. Untouched detail history is not retransmitted for a summary-only window update. Other generated rows use key-indexed INSERT or changed-column UPDATE; absent prior generated entities reject a partial snapshot.

## Preflight, staging and consistency

Remote `sync-data` is limited to read-only `--plan` or `--check-upstream`; apply requires a loopback endpoint and `--apply-rehearsal`. Reconciliation additionally requires explicit `--reconcile-monthly` or `--reconcile-manual` intent (`--force` is a manual alias). Without that intent, `--plan` observes hints only. The store independently rejects remote apply before reads. No environment variable silently enables production mutation.

Exact read metadata is required during keyset transaction/artifact snapshots. A 2,000,000-row per-run read ceiling bounds preflight; it is not account remaining quota. At about one million facts, an explicitly requested reconciliation still scans the full transaction corpus plus generated artifacts. Prior artifacts are hydrated for reuse and checked again for changed-only publication. Hint observation avoids these corpus reads even when timestamps change.

Default safety bounds are 1,000 changed transaction facts, 25,000 forecast writes, 100 atomic statements, 90,000,000 encoded HTTP-body bytes and 1,000,000 bytes per JSON parameter. These are local conservative controls, **not verified remote request/time limits**. Forecasts inspect existing indexes: inserts reserve record plus index entries; updates reserve old/new entries only for indexes referencing changed columns. Persistent cache INSERT OR REPLACE reserves both deletion and insertion. Account-wide remaining headroom is not available and cannot be inferred from these bounds.

Geocode/routing cache additions are staged in memory. Staged additions, transaction delta and every derived mutation are included in preflight and one local publication batch. Any partial upstream snapshot, missing entities, oversized delta/body or exceeded index-aware forecast fails before a D1 write. Amenity helper failures are collected for diagnosis; the coordinator rejects incomplete amenities rather than replacing good evidence with empty arrays.

The manifest baseline is captured before ingestion, checked before planning, and guarded inside the local batch. Transactions, caches and evidence publish together; manifest advances last. Native SQLite tests inject a mid-batch error, verify rollback of data/caches/manifest and replan/restage with a fresh client for retry. This establishes the tested **local adapter** contract only. REST batch envelope, atomicity, timeout recovery and D1 execution duration remain unproven, so the remote guard stays in place. Manifest-last across independent HTTP calls would not provide atomicity. Separate frontend requests can still span versions; an explicit client snapshot protocol is outside this change.

D1 Free currently allows account-wide 5,000,000 rows read/day, 100,000 written/day, 500 MB/database and 5 GB/account. REST and bindings fail after daily allowance exhaustion until midnight UTC. Other databases, dashboard/Wrangler inspections and bootstrap/index work share the quota. [Official limits](https://developers.cloudflare.com/d1/platform/limits/), [September 2026 enforcement](https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/).

## Public cache and query behavior

Successful public GET responses use explicit Workers Cache API. A 60-second cached manifest-version pointer plus versioned response is looked up before **any D1 read**. A pointer/response HIT performs zero D1 operations, including version discovery. A MISS reads manifest before/after the handler; a stale-pointer MISS discovers the current version first. Data fetched across a version change is not published under either version. A current-version response HIT after pointer expiry still pays one manifest read, honestly labeled separately.

Keys include SHA-256 of the complete published manifest, endpoint path and canonical validated handler parameters. Existing search parsers and suggestion normalization define canonicalization; ignored parameters cannot force repeated scans by varying cache keys. Remaining-lease search keys include UTC year. Cookie/authorization requests, private shortlist routes, errors, no-store/Set-Cookie responses and POST comparables are excluded. Cache failures do not rerun a successfully fetched handler. Pointer freshness is approximately 60 seconds and versioned objects have one-hour lifetimes. Cache API is data-center-local, not global or durable. [Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/).

Suggest reads a bounded compact block dictionary in indexed address-key pages plus MRT names. Manifest digest and block count validate a cold load. A shared **versioned dictionary** caches across DB objects/isolates in the same data center; distinct keystrokes reuse it without D1 LIKE scans. A short isolate cache coalesces simultaneous loads. Cache lookup/store failures fall back to valid D1 results. Town/street/block substring matching, exact/prefix ranking, postal prefix-only matching, MRT, aliases and caps remain; IME frontend behavior is unchanged. Cold dictionary reads and version checks still cost quota and must be measured remotely.

Old substring queries scan while prefix queries use existing NOCASE indexes. No index was casually added or removed. Actual production SQL plans/read costs are still blocked by authentication.

## Official source handling

Download uses official GET initiate-download → GET poll-download. 403/1010 denial stops the attempt; no intentional denial fallback, spoofed headers or bypass occurs. Optional `DATA_GOV_API_KEY` is scoped to official data.gov.sg API hosts, never OneMap/signed object downloads. Transient network/429/5xx backoff remains separate from D1 failures. [Official download flow](https://guide.data.gov.sg/developer-guide/dataset-apis/download-dataset).

Cheap probes fetch complete timestamp hints for resale child datasets, property, MRT and all enabled amenities. Invalid/missing upstream metadata fails closed. Timestamps are not immutable content revisions and are now observability only: changed hints, collection timestamps and seven-day age do not initiate reconciliation. The adopted [monthly/manual policy](neon-monthly-refresh-policy.md) requires explicit invocation, skips a monthly run after reconciliation already published in that UTC month, and permits manual intent independently. `--check-upstream` never scans the corpus. No schedule was created or activated. [Official dataset metadata](https://guide.data.gov.sg/developer-guide/dataset-apis/get-dataset-metadata).

## Reproducible local evidence

Run `vp run rehearse:d1-free /tmp/hdb-d1-rehearsal-report.json`. It creates/removes an isolated native SQLite database and replaces fetch **inside that process** with an explicitly emulated atomic HTTP adapter. No network or production connection opens. Machine-readable evidence (`docs/evidence/d1-free-synthetic.json`) records complete cardinalities, per-table native record changes, compiled HTTP bytes, computation counts and EXPLAIN output.

The dataset is deterministic synthetic historical-cardinality evidence: 985,399 → 985,533 transactions; 9,700 blocks/details/comparisons; 44,800 trends; 28 towns, eight fictional types, 200 observed months (2010-01 through 2026-08). It is not the actual Aug28/29 CSV or verified current production source. Generated data/storage sizes are synthetic. Native changed-record counts exclude index maintenance, and emulated HTTP metadata is not billing proof.

The +134 retry inserts zero additional facts and interruption rollback passed. Context candidate execution measured 40 ms and was rolled back; monthly native atomic publication measured 3,519 ms including local preflight and leaves 985,534 rows. Full build/plan/retry/worst-case/query rehearsal measured 47,818 ms and synthetic SQLite storage 434,688,000 bytes. These timings/storage are machine-specific native SQLite observations. Larger simultaneous ordinary upstream changes deliberately stop for review; no unbounded refresh or override is silently enabled. Actual remote D1 reads/writes/duration/account headroom remain **UNKNOWN** for every scenario.

Representative runtime SQL, local plans, returned-row counts and native timing are also recorded. Returned rows are never substituted for rows read: a COUNT readiness probe returns one row while scanning the blocks table. Refined search may require this additional readiness scan; its semantics remain truthful and response caching amortizes repeats rather than weakening filters.

No-change/source reorder computes zero block/trend/comparison entities and proposes zero generated writes; a manifest-only reconciliation still reserves one record. +1/+100/+134, modified-row explicit mapping, duplicate multiplicity, massive delta, interruption/retry, untouched entities, affected peers/trends, source ordering, metadata aggregation, shared cache MISS/HIT/version/parameter isolation, JSON patch values and staged cache recovery have automated coverage.
